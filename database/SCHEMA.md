# Database Schema — Draft

Database: `studybuddy`

Status: Proposed structure for team review. Field names and rules
must be coordinated with the API developer before validation is enforced.

## Users Collection

One document represents one student account and profile.

### Account Fields

| Field | MongoDB type | Purpose / rule |
|---|---|---|
| `_id` | ObjectId | Unique identifier generated by MongoDB |
| `firstName` | string | Required at registration; trim whitespace |
| `lastName` | string | Required at registration; trim whitespace |
| `email` | string | Required; trim and lowercase before storing; unique |
| `passwordHash` | string | Required for real password-based accounts; never store plaintext passwords |
| `emailVerified` | bool | Defaults to false; verification required before login |
| `profileComplete` | bool | Defaults to false; calculated by the API from profile requirements |
| `createdAt` | date | Account creation time |
| `updatedAt` | date | Last account or profile update |
| `isDemo` | bool | Defaults to false; true only for designated test profiles |

The API must validate the team's approved UCF email domain before
creating a real account. The exact allowed domain list needs agreement.

The existing demo profile uses an example.com address, is unverified,
and has no passwordHash. It is a test fixture and cannot log in.

### Profile Fields

| Field | MongoDB type | Purpose / rule |
|---|---|---|
| `major` | string or null | Required before profile is complete |
| `minor` | string or null | Optional |
| `gender` | string or null | Required before profile is complete; allowed values below |
| `genderPreference` | string | Defaults to `no_preference`; allowed values below |
| `semester` | string or null | Current course-selection term, such as `Fall 2026` |
| `courseIds` | array of ObjectId | References to courses._id; defaults to an empty array; no duplicates |
| `availability` | array of objects | Recurring weekly availability; defaults to an empty array |
| `availabilityConfirmedAt` | date or null | Last time the student confirmed their availability |

Allowed gender values:

- `male`
- `female`
- `other`
- `prefer_not_to_say`

Allowed genderPreference values:

- `no_preference`
- `male`
- `female`

A newly registered account may have an incomplete profile.

A complete profile requires a major, a gender selection, a current
semester, at least one valid course reference, and at least one
availability interval lasting 30 minutes or more.

The API determines profileComplete. Clients cannot simply set it to true.

### Availability Objects

Each entry uses:

| Field | Type | Rule |
|---|---|---|
| `dayOfWeek` | integer | 0 = Sunday through 6 = Saturday |
| `startMinute` | integer | Minutes after midnight; 0 through 1439 |
| `endMinute` | integer | Minutes after midnight; 1 through 1440; greater than startMinute |

Example:

```json
{
  "dayOfWeek": 1,
  "startMinute": 840,
  "endMinute": 960
}
```

This represents Monday from 2:00 PM to 4:00 PM.

Times represent recurring local campus times in `America/New_York`.

Intervals cannot cross midnight; split them into separate days.
The API should merge overlapping or adjacent intervals on the same day
to prevent double-counting available time.

When availabilityConfirmedAt is null or at least seven days old,
the application should prompt the student to confirm their schedule.
Whether stale availability excludes matching remains a team decision.

### Course References

courseIds stores course ObjectIds instead of copying course details
into every student profile.

The API must check that selected course IDs exist. MongoDB does not
automatically enforce foreign-key relationships.

Changing a course name should preserve its _id so existing references
continue to work.

### Indexes

- MongoDB's default unique `_id` index.
- `unique_user_email`: unique ascending index on `email`.

The API must normalize email casing consistently before storage and lookup.

### Matching Rules

Production matching excludes:

- The requesting student.
- Demo accounts.
- Unverified accounts.
- Incomplete profiles.
- Students from a different selected semester.
- Either member of a blocked pair.

Eligible students must share:

- At least one course.
- At least 30 consecutive minutes of availability.

Gender preferences must be respected in both directions.
A male/female preference matches only the corresponding gender value.

Additional shared courses, availability overlap, and major/minor
similarity may contribute to ranking. Final weights are not yet agreed.

### API Privacy Rules

Never return passwordHash in API responses.

Candidate search responses must omit email addresses.
Contact email may be returned only after an authorized check confirms
an accepted contact request and no block between the two students.

Revoking access prevents future email retrieval but cannot erase
an address someone already copied.

### Decisions Still Requiring Review

- Exact allowed UCF email domains.
- Password-hashing implementation shared with the API.
- Final semester naming and rollover behavior.
- Whether stale availability excludes matching.
- Final ranking weights.
- Validation rules for contactRequests, blocks, and authTokens.
